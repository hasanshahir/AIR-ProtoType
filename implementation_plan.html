1 Executive Summary & The "Why"

Why Rebrand as an Independent Site?

The current site (cct.neduet.edu.pk/AIR) is an outdated subpage under the departmental directory. Top global labs (e.g., Stanford AI Lab ai.stanford.edu, Allen AI allenai.org) operate independent portals. A dedicated web presence establishes authority for international grants, corporate industry partnerships, and researcher recruitment.

Why the MERN Stack?

University faculty require a dynamic Admin Dashboard where faculty and RAs can update publications, add graduating student batches, and announce research vacancies without writing code or filing tickets with university network administrators.

Core Architectural Objective: Build a high-performance single-page application (React + Vite + Tailwind CSS) powered by a lightweight Node.js/Express REST API and MongoDB Atlas. It features a decoupled design: if the backend or database ever undergoes maintenance, the public frontend seamlessly serves cached data without disruption.

3 Detailed Feature Architecture & Technical Specifications

A. The Vacancy Indicator Feature

Problem: Faculty receive dozens of redundant emails weekly asking about research assistantships, FYDP supervision openings, and internships.

Solution: A real-time vacancy module controlled via the Admin Panel that displays live badges across the homepage and careers page:

  • OPEN Active Vacancies: Displays available slots (e.g., "2 RAs for Regional LLM Project", "1 Undergraduate FYDP Group") with application deadline and direct submission link.
  • REVIEWING Reviewing Applications: Submissions closed; committee evaluating candidates.
  • CLOSED No Vacancies: Displays notice with date for the next recruitment cycle.

4 Web Dev Industry Consensus (Mitigating Academic Lab Pitfalls)

Real-World Risk Why Most Student Sites Fail Our Strategic Mitigation
1. The "Graduation Trap" When developers graduate, unmaintained custom servers crash or database credentials expire, causing the website to go dark. Decoupled JSON Fallback: The React app builds static cache fallbacks. If the Node/MongoDB server goes down, the frontend still renders complete lab data gracefully.
2. Admin Over-Engineering Teams try building a complex drag-and-drop CMS from scratch, run out of time, and leave half-working forms. Focused CRUD Forms: Pre-built, robust table and modal components strictly tailored to the 5 core models, keeping maintenance zero-friction.
3. Image Storage Bloat Storing raw 8MB event photos in the database or server disk slows page loads and consumes disk quota. Automated Cloud CDN: Integrate Cloudinary free tier with automatic web compression and auto-format (f_auto, q_auto).
